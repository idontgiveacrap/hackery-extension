Scripts run in the page hook for fetch/XHR only. webRequest keeps declarative block/redirect/header/body actions (Firefox MV3 CSP blocks new Function() in extension pages). Script receives ctx with phase, method, url, pageUrl, headers, body, status, plus ctx.sharedState (persisted across navigations) and ctx.tabState (per tab). Set ctx.logDetail to surface text in Recent matches. Request scripts also receive decodeBasicAuth(ctx), which returns decoded Basic credentials from headers or URL userinfo. Return modified ctx to apply script changes, null to block, or nothing to leave wire fields unchanged (regex replacements still apply). Unchanged requests pass through as-is.

Hook behavior

When a rule script triggers fetch/XHR, other rules are skipped unless they opt in below. A rule never matches its own traffic while running.

Untested intent

Header forwarding on redirect (e.g. preserving Authorization when a page-hook redirect changes the XHR URL) is not implemented. Fetch/XHR header mods for Cookie, Origin, and Referer use a dummy x-hackerylab-* prefix in the page hook; webRequest rewrites them to the real names before the request is sent. Other resource types get header rules directly via webRequest.
